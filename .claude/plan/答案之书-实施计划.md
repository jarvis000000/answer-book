# 答案之书 · 实施计划

> 状态：**已完成**（2026-10-04 启动并当天交付）
> 目标：把《高性价比人生指南》657 条建议改造成一个「提问 → 命中相关答案」的问答系统，
> 每条答案带结构化标签（年龄 / 性别 / 领域 / 主题），前期离线匹配，后期可接 LLM。

## 实施结果（2026-10-04 收尾）

六个阶段全部完成，交付物与验收情况：

| 阶段 | 内容 | 结果 |
|------|------|------|
| P1 | 解析器 md → entries.json | 657 条 / 34 节，**零警告**；A/B/C 分级 431/174/52，与上游徽章逐项一致 |
| P2 | 标签体系 + 规则打标 | 5 个维度、24 领域 / 44 主题 / 14 人群；定向断言覆盖典型条目 |
| P3 | 检索：bigram + BM25 + 查询解析 + 排序 | 评测集 hit@1 81.3% · hit@3 96.9% · hit@5 100% · MRR 0.886 |
| P4 | CLI | `npm run ask`，支持交互模式、`--json`、`--browse`、安全提示 |
| P5 | Web UI | 零依赖单页，「铅印典籍」风格，含夜读模式；零控制台错误 |
| P6 | 测试 + 文档 | 62 条测试全绿；README 写清用法、算法取舍与许可 |

**与计划的偏差**（都是实施中发现更好做法后改的）：

1. **补了两份人工词典资产**，计划里没写：`data/synonyms.json`（90 条查询同义词）。
   原计划以为关键词 BM25 够用，实测发现中文二元组切分无法建立「裁员 → 辞退」这类对应关系，
   而真词和跨词边界碎片又无法用词频区分（两者文档频率都极低）。这是离线和 LLM 之间的必经补丁。
2. **排序算法比计划复杂**：原计划的固定权重（关键词 0.55 / 标签 0.45）实测区分度不够，
   改成按「查询信息量」动态配比，并把 BM25 的线性归一化换成压缩式归一化。
   具体理由写在 `src/search/rank.mjs` 的注释里。
3. **标签判定从「标题+正文」收紧到「标题优先」**：早期版本让正文命中参与性别判定，
   结果 48 条「女性专属」里混进一堆（正文提到女性研究人群就被误判），
   改成标题说了算、正文只在标题没提时以 3 处以上单侧命中兜底。
4. **一个已知未解决问题**：「体检报告说血压高」这类句式，正确条目排第 5。
   试过的修法都会连带弄坏别的用例，选择不加特例规则，详见 README 末节。

**验证方式**：`npm test`（73 条）+ `npm run eval`（32 条标注用例）都可重复运行，
调参后的效果变化有数字可依，不靠手感。

## 第二轮：界面改版（2026-10-04 当天）

用户反馈第一版的「铅印典籍」风格**太老气、不直观**，提出六条具体要求。逐条落地：

| 要求 | 做法 |
|------|------|
| 风格明亮清新 | 换成薄荷绿主色 + 天蓝辅色 + 浅色光晕背景；圆角胶囊取代铅印直角；字重减轻 |
| 提问区明显且滚动固定 | 搜索框做成顶栏胶囊，`position: sticky`；滚过 16px 自动收成紧凑形态 |
| 卡片 + 点击弹窗 | 结果改为卡片网格；点卡片弹出详情（成本/收益/备注/原文链接/排序理由） |
| 看到所有相关的 | 一次取回最多 60 条，「显示更多」逐批展开 + 「展开全部」；顶部标明候选数与相关数 |
| 多种排序切换 | 新增 `src/search/sort.mjs`：相关性 / 证据等级 / 性价比 / 成本最低 / 章节顺序 |
| 更直观 | 证据等级做成色点、性价比做成三段小柱，不用读文字就能扫 |

**为支持「看到所有相关的」顺带修掉一个真问题**：原来的相关性裁剪用的是绝对阈值
（`tagScore > 0.2 || keywordScore > 0.35`），但标签分有个约 0.25 的地板——任何条目都能越过它，
于是「相关」形同虚设（问「幽门螺杆菌」时有 294 条被判为相关）。
改成跟着每条查询自己分数尺度走的相对阈值（`0.55 × 最高分`）后，
具体问题留 3~6 条、泛问题留 26~47 条，这才是有意义的「相关」。

**过程中修掉的两个真 bug**：

1. `display: grid` / `flex` 盖掉了浏览器给 `[hidden]` 的 `display: none`，
   导致「隐藏」的弹窗在首屏就显示出来。加了一条全局 `[hidden] { display: none !important }` 兜底。
2. 自动滚动把「理解为」那条正好卡在吸附顶栏与工具栏之间露出半截。
   改成以「理解为」为锚点，而不是拿吸附元素（工具栏）当锚点。

## 1. 需求拆解

用户原话：

> 我提出问题，然后你在里面找到相关性高的答案。
> 例如：我是一个 45 岁女性，我需要注意哪些身体健康方面的问题。一个 6 岁儿童有哪些建议和指南。
> 将每个答案额外做好标记，年龄性别涉及领域等标签。然后根据问题找到相关标签的答案。
> 后期可能会链接 llm 来匹配，前期主要是以离线匹配为主。

拆成四件事：

| # | 事情 | 交付物 |
|---|------|--------|
| A | 把源书正文变成结构化条目 | `data/build/entries.json` |
| B | 给每条打标签：年龄 / 性别 / 领域 / 主题 | `data/build/entries.json` 的 `tags` 字段 |
| C | 把「人话问题」解析成结构化查询，再按标签 + 关键词召回排序 | `src/search/*` |
| D | 给人用的入口：命令行 + 本地网页 | `src/cli.mjs`、`src/server.mjs`、`web/*` |

## 2. 数据源

- 上游原书：`github.com/eternity4719/HowToLiveBetter`，内容 CC BY 4.0，代码 MIT。
- 34 个章节文件、657 条建议，落在 `data/source/*.md`（原样复制，不修改）。
- 每条的结构固定：

```markdown
### 12. 标题（动词开头的建议）
<!-- 成本标签: 钱=0|少|多 时间=少|中|多 毅力=否|些|是 收益=大|中|小 口径=死亡率|金钱|时间|自由 -->
- 成本：……
- 说人话：……
- 收益：……
- 证据等级：A|B|C
- 来源：……
- 备注：……
```

- 性价比档位不来自源文，按上游规则现场合成：
  `成本分 = 权重(钱) + 权重(时间) + 权重(毅力)`，权重 `0/少/否 = 0`、`少/中/些 = 1`、`多/是 = 2`；
  收益大且成本分 = 0 → 极高；收益大且成本分 ≤ 2，或收益中且成本分 = 0 → 高；其余 → 一般。

## 3. 标签体系（本项目的核心资产）

五个维度，每条条目带其中一部分：

| 维度 | 取值 | 来源 |
|------|------|------|
| `ages` 年龄段 | 婴儿 / 幼儿 / 学龄 / 青少年 / 青年 / 中年 / 老年 / 全龄 | 标题和正文里的年龄词、显式年龄数字 |
| `gender` 性别 | male / female / any | 「孕妇」「前列腺」「HPV」这类专属词 |
| `domains` 领域 | 健康·急救·安全·法律·财务·职业·创业·育儿·婚恋·住房·教育·出行·心理·信息·养老·残疾·消费·身后事·减压 | 章节号为主，条目标题关键词修正 |
| `topics` 主题 | 疫苗 / 癌症筛查 / 安全带 / 立案 / 仲裁 …… | 标题关键词表 + 书名号里的法规名 |
| `audience` 人群场景 | 司机 / 程序员 / 骑手 / 租客 / 家长 …… | 关键词表 |

另有两个**源生标签**直接沿用，不重新定义：

- `grade` 证据等级 A/B/C
- `ratio` 性价比档 极高/高/一般
- `caliber` 口径 死亡率/金钱/时间/自由
- `cost` 成本三项（钱/时间/毅力）

**打标签的策略**：规则优先、词典驱动、可人工覆盖。
`data/taxonomy.json` 放词典和章节映射，`src/build/classify.mjs` 执行规则，
`data/overrides.json` 允许人工逐条改标签（机器结果与人工判断分开存放）。
标签由**词表命中**决定，不靠模型猜——这样每次重建结果可复现、可 diff。

## 4. 匹配方案

### 4.1 查询解析（`src/search/parse-query.mjs`）

把「我是一个 45 岁女性，需要注意哪些身体健康问题」解析成：

```json
{ "age": 45, "ageBands": ["中年"], "gender": "female", "domains": ["健康"],
  "keywords": ["健康", "身体"], "raw": "……" }
```

规则：年龄用正则抓阿拉伯数字和中文数字（「45 岁」「六岁」「60 岁以上」），
性别抓「女性 / 男性 / 孕妇 / 宝妈 / 爸爸」这类词，
领域走领域关键词表，剩下的字符做关键词召回。

### 4.2 召回（`src/search/index.mjs`）

零依赖中文检索：**字符 bigram 倒排索引 + BM25**。
中文不引入分词词典，用二元组切分（「安全带」→ 安全/全带）——对短文本检索足够稳，
且不依赖任何外部包。英文和数字单独成 token。

候选集来自三路并集：bigram 命中、领域标签命中、年龄/性别标签命中。

### 4.3 排序（`src/search/rank.mjs`）

综合分 = `BM25 归一化分 × 0.55 + 标签分 × 0.45`，标签分再拆：

```
标签分 = 领域命中 0.40 + 年龄段命中 0.30 + 性别命中 0.20 + 人群命中 0.10
性别不匹配（问女性却命中男性专属条）直接降到候选集末尾，不是加分项
```

再乘两个温和的调节系数：证据等级（A 1.0 / B 0.95 / C 0.9）、性价比档（极高 1.0 / 高 0.98 / 一般 0.95）。
调节系数只做同分排序的微调，不改变「标签和关键词才是主因」这个前提。

### 4.4 LLM 预留（`src/llm/adapter.mjs`）

定义 `QueryPlanner` 接口，两个实现：

- `rulePlanner`（默认）：第 4.1 节的纯规则解析。
- `llmPlanner`（可选）：同一份接口，把问题交给 LLM 输出结构化查询 + 重排。
  读环境变量 `ANSWER_BOOK_LLM_BASE` / `ANSWER_BOOK_LLM_KEY` / `ANSWER_BOOK_LLM_MODEL`，
  没配就自动退回 `rulePlanner`。

**离线路径永不被绕过**：LLM 只负责「把问题解析得更准」和「对候选重排」，
答案正文始终来自本地 657 条，不生成新内容——避免模型编造数字。

## 7. 边界与风险

- **不生成新内容**：所有答案正文逐字来自源书，出处写到「第 X 节第 Y 条」。
- **不是医疗/法律建议**：沿用源书定位，页面与 CLI 都带免责声明。急症 / 自杀念头 / 法律程序三类
  问题优先给「立刻做什么」，跟源书 skill 的处理一致。
- **标签是启发式**：规则打标必然有错，靠 `overrides.json` 修，不指望一次到位；
  评估口径写成可复跑的脚本，不靠「看起来对」。
